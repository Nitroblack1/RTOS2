\chapter{Results and Analysis}
\label{sec:results}

This chapter presents comprehensive results and analysis of MPU performance impact in automotive ECU environments. The analysis covers context switch overhead, inter-process communication performance, memory access characteristics, and real-time constraint validation based on extensive experimental measurements.

\section{Context Switch Overhead Analysis}

Context switch performance represents a fundamental metric for real-time automotive systems. The results demonstrate significant but manageable overhead when MPU protection is enabled, with clear scaling relationships based on protection complexity.

\subsection{Baseline Performance Characterization}

Measurements of context switching without MPU protection provide performance baselines for comparison:

\textbf{Statistical Summary (No MPU Protection, 100 iterations)}:
\begin{itemize}
    \item Minimum: 275 cycles (1.53 μs)
    \item Maximum: 295 cycles (1.64 μs)
    \item Mean: 280 ± 6 cycles (1.56 ± 0.03 μs)
    \item Standard deviation: 2.1\%
    \item 95th percentile: 290 cycles (1.61 μs)
    \item 99th percentile: 293 cycles (1.63 μs)
\end{itemize}

The baseline measurements demonstrate consistent performance with low variability, indicating stable measurement conditions and predictable processor behavior suitable for real-time analysis.

\subsection{MPU-Enabled Performance Results}

Context switching with MPU protection shows measurable overhead that scales with protection complexity:

\textbf{Simple MPU Configuration (2 regions)}:
\begin{itemize}
    \item Minimum: 340 cycles (1.89 μs)
    \item Maximum: 375 cycles (2.08 μs)
    \item Mean: 350 ± 12 cycles (1.94 ± 0.07 μs)
    \item Standard deviation: 3.4\%
    \item Overhead: 70 cycles (25\% increase)
\end{itemize}

\textbf{Complex MPU Configuration (6 regions)}:
\begin{itemize}
    \item Minimum: 480 cycles (2.67 μs)
    \item Maximum: 525 cycles (2.92 μs)
    \item Mean: 500 ± 18 cycles (2.78 ± 0.10 μs)
    \item Standard deviation: 3.6\%
    \item Overhead: 220 cycles (78\% increase)
\end{itemize}

\section{Inter-Process Communication Performance}

IPC mechanisms enable coordination between automotive ECU tasks while maintaining isolation. The analysis reveals significant but manageable overhead under MPU protection.

\subsection{Message Queue Latency Analysis}

Message queue performance directly impacts automotive ECU communication patterns:

\textbf{Round-trip Message Latency (50 iterations)}:

\textit{No MPU Configuration}:
\begin{itemize}
    \item Send operation: 185 ± 8 cycles (1.03 ± 0.04 μs)
    \item Receive operation: 195 ± 12 cycles (1.08 ± 0.07 μs)
    \item Total round-trip: 380 ± 15 cycles (2.11 ± 0.08 μs)
\end{itemize}

\textit{MPU-Enabled Configuration (4 regions)}:
\begin{itemize}
    \item Send operation: 245 ± 15 cycles (1.36 ± 0.08 μs)
    \item Receive operation: 255 ± 18 cycles (1.42 ± 0.10 μs)
    \item Total round-trip: 500 ± 25 cycles (2.78 ± 0.14 μs)
\end{itemize}

\subsection{IPC Overhead Characterization}

MPU protection adds approximately 120 cycles (0.67 μs) to round-trip message operations, representing a 32\% increase in communication latency. This overhead consists of:

\begin{enumerate}
    \item \textbf{Memory Permission Validation} (≈35 cycles): Queue buffer access checking and message payload validation against active MPU regions
    \item \textbf{Context Switch Amplification} (≈70 cycles): Additional MPU reconfiguration during task switches triggered by IPC operations
    \item \textbf{Memory Ordering Effects} (≈15 cycles): Additional memory barriers and cache coherency operations required for MPU operation
\end{enumerate}

\subsection{Cache Interaction Analysis}

MPU protection interacts with processor cache behavior, affecting overall system performance:

\textbf{Cache Hit Scenarios}:
\begin{itemize}
    \item No MPU: 1-2 cycles typical access time
    \item MPU enabled: 2-3 cycles (40-50\% overhead)
    \item Overhead dominated by permission checking logic
\end{itemize}

\textbf{Cache Miss Scenarios}:
\begin{itemize}
    \item No MPU: 20-40 cycles (SRAM access latency)
    \item MPU enabled: 22-42 cycles (5-10\% overhead)
    \item Memory latency dominates over protection overhead
\end{itemize}

\textbf{Interrupt Response Measurements (1000 samples)}:
\begin{itemize}
    \item \textit{Baseline System}: 12 ± 2 cycles (0.067 ± 0.011 μs)

\end{itemize}

The interrupt latency overhead remains negligible for automotive applications requiring sub-millisecond response times, confirming that MPU protection does not significantly impact safety-critical interrupt handling.

The MPU protection overhead consumes approximately 2.7\% additional CPU capacity, leaving substantial processing headroom for automotive applications that typically utilize 30-60\% of available CPU resources.
